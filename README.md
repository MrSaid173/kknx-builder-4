# KKNX builder (Redmi 8 / 8A, olive / pine)

Собирает ядро KKNX (4.9.337, `danya2271/kernel_xiaomi_sdm439`, коммит `124dcdc99803`) на GitHub Actions.
Частоты CPU не меняются: сборка прерывается, если контрольная сумма CPU-таблиц разошлась.

## Как собрать

1. Залейте содержимое архива в свой репозиторий на GitHub.
2. **Actions → Build KKNX kernel (mi439) → Run workflow**, выберите поля (ниже), нажмите Run.
3. Готовый `KKNX-gpu…zip` лежит в Artifacts (рядом `build-info.txt`: что вошло в сборку). Прошивайте через recovery.
4. Не загрузилось: прошейте рабочий `KKNX-800Mhz_v2.zip`, а в новой сборке верните твики в «как раньше» (набор ниже).

## Менеджер и ядро

Менеджер ReSukiSU и ядро должны быть одной версии (UAPI). Если UAPI ядра выше, чем у менеджера, приложение пишет «Manager update required». По умолчанию ядро собирается под последний релиз со страницы Releases, поэтому подходит релизный APK. В `build-info.txt` и в итоге запуска (Summary) есть строка `manager:` с тегом релиза и версией. Если ни API GitHub, ни лента релизов недоступны, сборка останавливается, а не берёт молча последний коммит: повторите запуск или задайте `resukisu_ref` явно.


Подробности про LOLZ, GPU, root и установщик: [docs/DETAILS.md](docs/DETAILS.md).

## Твики

Ускоряют ядро, не отнимая энергосбережение: нет governor `performance`, фиксированных частот и отключения сна CPU.
Частоты, напряжения и таблицы шины не затрагиваются. Каждый твик отдельное поле. Числа выбраны по логике, **ничего не замерялось**.

Уровень риска: **низкий** = худший случай «нет эффекта»; **средний** = возможны сбои, образ грузится; **высокий** = возможна потеря функции системы.

### Какие поля работают только парой

- `cpu_boost = да` работает только если в `runtime_tune` есть `boost`. Без неё драйвер включён, но частоты не заданы. Группа `boost` без `cpu_boost` игнорируется.
- `io_sched = cfq` даёт полный эффект, только если в `runtime_tune` есть `io` (иначе у CFQ остаётся штатное ожидание между запросами).
- Группа `sched` из `runtime_tune` действует, только когда активен schedutil (из `default_gov` или выставлен прошивкой).

### `io_sched` (по умолчанию `cfq`; `deadline`, `keep`)

- **Делает:** собирает CFQ и deadline, выбранный ставит по умолчанию. С cfq включается `CFQ_GROUP_IOSCHED`: в стандартном init Android фоновой группе даётся меньший вес ввода-вывода, и он работает только в CFQ. С noop фон и передний план делят eMMC поровну.
- **Риск:** низкий. Выигрыш не измерен; если у вашей eMMC включена командная очередь (CMDQ), разница с noop может быть малой.
- **Сочетается:** с любым другим полем; лучше всего с группой `io`. `deadline` проще, но весов групп не знает: берите его, если cfq вызовет странности.
- **Откат:** `keep` (вернётся noop).

### `default_gov` (по умолчанию `schedutil`; `keep`)

- **Делает:** governor по умолчанию schedutil вместо performance (так в defconfig автора). Действует, пока прошивка не выставит свой.
- **Риск:** низкий. Если прошивка сама выставляет governor, поле ни на что не влияет.
- **Сочетается:** с группой `sched` (её значения применяются только при schedutil) и с `cpu_boost` (подъём при касании закрывает паузу, пока governor поднимает частоту).
- **Откат:** `keep`.

### `cpu_boost` (по умолчанию да)

- **Делает:** включает драйвер `cpu_boost` (код был в дереве, но выключен). При касании экрана на 80 мс поднимает минимальную частоту: CPU0–3 до 1305,6 МГц, CPU4–7 до 1171,2 МГц. Работает с любым governor.
- **Риск:** низкий. Чуть больше расход на каждое касание; если perf HAL прошивки тоже поднимает частоту, подъёмы могут дублироваться.
- **Сочетается:** нужна группа `boost` в `runtime_tune` (см. выше). С любым `default_gov`.
- **Откат:** `нет`.

### `zram_comp` (по умолчанию `lz4`; `zstd`, `lzo`, `keep`)

- **Делает:** задаёт алгоритм сжатия, который ядро ставит новому zram-устройству. Размер zram и swappiness задаёт не ядро, а прошивка.
  - `lz4`: быстрее и дешевле по CPU, сжимает слабее.
  - `zstd`: плотнее, но заметно дороже по CPU на A53. Берите, если не хватает памяти.
  - `lzo`: как в исходном defconfig. `keep`: что дал порт LOLZ (`full` = zstd, иначе lzo).
- **Риск:** низкий. Если прошивка сама пишет `comp_algorithm`, поле ничего не меняет. Проверка: `cat /sys/block/zram0/comp_algorithm` (активный в скобках).
- **Сочетается:** с любым `lolz_port`; при `lolz_port=full` это поле главнее. Значения группы `vm` подбирались в расчёте на lz4: при `zstd` уберите `vm`, если заметите нагрев при выгрузке памяти.
- **Откат:** `keep`.

### `runtime_tune` (по умолчанию `io,vm,sched,boost`; пусто = нет)

- **Делает:** ставит `/vendor/etc/init/init.kknx.rc`. Он срабатывает после скриптов прошивки (`vendor.post_boot.parsed=1`, как `init.lolz.rc`). Группы, лишнюю удалите из поля:
  - `io`: eMMC `mmcblk0`: планировщик из `io_sched`; для cfq `slice_idle 0`; `read_ahead_kb 256`; `add_random 0`.
  - `vm`: `swappiness 100`, `page-cluster 0`. Вернуть страницу из zram дешевле, чем перечитать из eMMC, поэтому анонимную память выгодно выгружать охотнее кэша файлов.
  - `sched`: у schedutil на обоих кластерах `up_rate_limit_us 500`, `down_rate_limit_us 20000`, `iowait_boost_enable 1`.
  - `boost`: частоты и длительность `cpu_boost`.
- **Риск:** низкий. Недоступные узлы init пропускает. Если службы прошивки (perf HAL, у MIUI своя настройка памяти) переписывают те же значения позже, они перекроют rc; при конфликте с памятью уберите `vm`.
- **Сочетается:** см. «работают только парой». Исключение: при `net_cc=bbr` файл создаётся даже с пустым полем (будет одна строка про fq).
- **Откат:** пустое поле. Установщик сам удалит `init.kknx.rc` от прошлой прошивки.

### `net_cc` (по умолчанию `keep`; `bbr`)

- **Делает:** TCP BBR по умолчанию вместо westwood, собирается `fq`, в rc пишется `default_qdisc fq` (в 4.9 BBR без fq не работает как задумано).
- **Риск:** средний, выгода узкая: заметно только на отдаче (upload, раздача). fq получают интерфейсы, созданные после запуска rc; созданные раньше остаются как были.
- **Сочетается:** с любыми полями. Проверка: `cat /proc/sys/net/ipv4/tcp_congestion_control`.
- **Откат:** `keep`.

### `cc_opt` (по умолчанию `keep`; `inline`)

- **Делает:** убирает из `Makefile` три строки `-inline-threshold=1`, `-inlinehint-threshold=1`, `-unroll-threshold=1`, которые почти выключают инлайнинг и разворот циклов. Остаются штатные пороги clang.
- **Риск:** средний. Прирост не измерен. Образ растёт (сейчас `Image.gz-dtb` 14,4 МБ; итоговый размер в `build-info.txt`); если он не влезет в раздел, установщик прервёт прошивку, не записав его.
- **Сочетается:** независим от остальных, но проверяйте его отдельной сборкой: ошибка компилятора проявляется не сразу и в случайных местах.
- **Откат:** `keep`.

### `spf` (по умолчанию нет)

- **Делает:** включает Speculative Page Fault: часть page fault обрабатывается без `mmap_sem` (быстрее запуск многопоточных приложений). Хуки в `arm64` уже есть, в defconfig автора опция выключена.
- **Риск:** средний, на железе не проверено. Ошибки в работе с памятью проявляются как случайные вылеты приложений или паника ядра.
- **Сочетается:** независим, но не включайте его в одной тестовой сборке с `lmk=psi`: оба правят работу с памятью, виновника не найдёте.
- **Откат:** `нет`.

### `lmk` (по умолчанию `kernel`; `psi`)

- **Делает:** `psi` включает PSI (в дереве есть интерфейс триггеров, нужный lmkd) и убирает встроенный LMK ядра.
- **Риск:** **высокий**, на железе не проверено. Нужна прошивка Android 10+, где lmkd работает по PSI. Если lmkd старого типа, убийцы процессов не будет (memcg в этом ядре выключен), и при нехватке памяти телефон зависнет.
- **Сочетается:** с `vm` из `runtime_tune` (память тогда держит lmkd). Проверка после прошивки: есть `/proc/pressure/memory`; в `logcat -s lowmemorykiller` ожидайте упоминание psi.
- **Откат:** `kernel`.

## Готовые наборы

| Набор | Поля |
|---|---|
| **По умолчанию** (как стоит в workflow) | `io_sched=cfq`, `default_gov=schedutil`, `cpu_boost=да`, `zram_comp=lz4`, `runtime_tune=io,vm,sched,boost`, остальное выключено |
| **Как раньше** (ни одного твика) | `io_sched=keep`, `default_gov=keep`, `cpu_boost=нет`, `zram_comp=keep`, `net_cc=keep`, `lmk=kernel`, `cc_opt=keep`, `spf=нет`, `runtime_tune=` пусто |
| **Расширенный** (после того как по умолчанию заработал) | по умолчанию + `cc_opt=inline`, затем при желании `net_cc=bbr` |

В «как раньше» скрипт пишет «все твики выключены: сборка идентична прежней» и не меняет ни исходники, ни `.config`.

## Если телефон не грузится

1. Соберите набор «как раньше». Грузится: причина в твике. Включайте их по одному в порядке этого списка: `io_sched`, `default_gov`, `cpu_boost`, `zram_comp`, `runtime_tune`, затем `cc_opt`, `net_cc`, `spf`, `lmk`.
2. Не грузится и «как раньше»: причина не в твиках. Порядок поиска (root, LOLZ, GPU, компилятор): [docs/DETAILS.md](docs/DETAILS.md#порядок-проверки-если-телефон-не-грузится-root-lolz-gpu).

## Что проверено

В песочнице (тулчейн `ubuntu_clang16`, одно ядро CPU): скрипт твиков на реальном дереве во всех режимах, применение опций в `.config`, компиляция всех затронутых файлов, прогон установщика с подставными командами.
**Не проверено:** линковка целого образа с твиками, загрузка на устройстве, прирост от каждого твика, `lmk=psi` и `spf` на железе. Полный список: [docs/DETAILS.md](docs/DETAILS.md#что-проверено-а-что-нет).
